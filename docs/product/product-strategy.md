# Product strategy and defensible position

## Honest current category

SYSCORA 0.1.x is a supervised Windows developer preview, not a universal
consumer assistant. Its strongest product thesis is not “another agent that can
click.” It is **evidence-first computer agency**: observe through structured
machine interfaces when possible, bind actions to explicit authority, and make a
success claim reachable only through independent evidence.

## Candidate USP

> The Windows agent that proves what it changed.

Supporting advantages are structured accessibility/DOM perception that can be
cheaper and more deterministic than screenshot-only loops; a typed capability
layer; explicit content-versus-authority boundaries; and local, inspectable
audit/undo state. These are architectural advantages, not yet market leadership.

## What is not defensible yet

- “More accurate than Claude computer use, OpenAI's computer-use products, or
  other commercial agents” is unproven without a shared independent benchmark.
- A private task suite is not comparable to OSWorld or a competitor's published
  evaluation.
- Local-first does not mean private when required context is sent to an external
  model provider.
- A large test count does not establish safe generalization across Windows apps.
- No moat exists merely because the agent uses accessibility APIs, OCR, or CDP;
  competitors can reproduce mechanisms.

## Path to a venture-scale company

The plausible wedge is high-consequence, cross-application Windows work where
proof, control, auditability, and recovery matter more than a flashy demo. Start
with one painful workflow and measurable ROI—such as governed back-office
operations or developer/IT desktop procedures—then build proprietary reliability
data, verified workflow primitives, enterprise policy, and integrations around
it. A horizontal “for everyone” launch before that wedge creates support burden
without differentiation.

Consumer readiness additionally requires a managed inference/account/billing
service, abuse controls, real support operations, telemetry with consent,
onboarding that never mentions provider keys, and a distribution/legal entity.
Those are company capabilities, not changes that can be honestly simulated in a
desktop repository.

The billion-dollar outcome is possible only as an execution hypothesis. The
current code does not establish product-market fit, distribution, retention,
unit economics, or a durable data/network moat. The evidence architecture is a
credible seed for a company; it is not itself proof of one.
